# AutoClip — ТЗ для агента

Ты дорабатываешь AutoClip — десктопное приложение для Windows, которое нарезает длинные записи
стримов на короткие вертикальные клипы для TikTok, YouTube Shorts и Instagram Reels.
Владелец — Гоша, русскоязычный стример (канал Final_KFC_Boss). Общайся с ним по-русски,
простыми словами, без жаргона. Он не программист в этой области: объясняй, что делать, по шагам.

---

## 1. Окружение

- Windows 11, видеокарта NVIDIA RTX 5080, процессор Ryzen 9 9950X3D.
- Основной монитор ультраширокий 3440×1440, есть второй монитор.
- Python 3.11–3.14, 64-бит (рекомендуется 3.13). На 3.15 нет готовых сборок `ctranslate2`,
  поэтому faster-whisper не ставится. Все пакеты ставить с `--only-binary=:all:`.
  Python может быть не в PATH: `install.bat` и `AutoClip.bat` ищут его через лаунчер
  `py -3.13` / `pyw -3.13` (с откатом на 3.12, 3.14, 3.11 и на `python`). Делай так же.
- ffmpeg 9.x (полная сборка gyan.dev, с libass и NVENC) установлен в систему, есть в PATH.
- Запись делается в OBS: вертикальный холст 1080×1920, вебка и игра в одном кадре
  (по умолчанию вебка сверху, игра снизу).
- Записи длятся от нескольких минут до нескольких часов.

## 2. Что уже есть (версия 1)

Файлы в папке:

| Файл | Что это |
|---|---|
| `autoclip.py` | Ядро: вся обработка. Работает и из консоли (`python autoclip.py запись.mp4`). |
| `gui.py` | Окно на tkinter + tkinterdnd2: перетаскивание видео, настройки, лог. |
| `install.bat` | Установка зависимостей (faster-whisper, numpy, tkinterdnd2, CUDA-библиотеки). |
| `AutoClip.bat` | Запуск окна через pythonw. |
| `звуки/` | Создаётся при запуске: встроенные звуки для мата + свои файлы пользователя. |
| `настройки.json` | Сохранённые настройки окна. |

Как работает `autoclip.process(video)`:

1. `extract_audio` — звук в WAV 16 кГц моно.
2. `loudness_per_second` — громкость каждой секунды (читает кусками, память не съедает).
3. `transcribe` — faster-whisper `large-v3`, `language="ru"`, `word_timestamps=True`,
   `vad_filter=True`, `condition_on_previous_text=False`. Сначала пробует CUDA float16, потом
   CPU int8. На Windows добавляет пути к DLL из pip-пакетов `nvidia-*` (`_windows_cuda_dlls`).
   Результат кэшируется в `<запись>.transcript.json` рядом с видео.
4. `llm_moments` — необязательно. Режим `auto`: Ollama (`localhost:11434`, модель
   `qwen2.5:14b`), иначе Claude API, если задан `ANTHROPIC_API_KEY` (модель
   `claude-haiku-5-5`), иначе без модели. Расшифровка уходит кусками по 10 минут, модель
   возвращает JSON с моментами `{start, end, score, title, reason}`.
5. `score_timeline` — оценка каждой секунды: громкость относительно фона (скользящая
   медиана 2 мин, z-оценка через MAD), смех в речи, восклицания, мат, плотность речи,
   оценка модели. Сглаживание окном 5 с.
6. `pick_clips` — выбор пиков, клипы 15–55 с, привязка к границам фраз, зазор между
   клипами, точки зума (самые громкие секунды внутри клипа).
7. `render_clip` — один вызов ffmpeg на клип:
   - видео в родном разрешении, горизонтальное обрезается по центру под 9:16;
   - зум через `scale ... eval=frame` + `crop`;
   - субтитры ASS: 2–3 слова, текущее слово жёлтое, мат показан как `П*****`;
   - мат: оригинальный звук глушится на слове, поверх накладывается выбранный звук
     (`asplit` → `atrim` → `adelay` → `amix`);
   - кодирование `h264_nvenc` с откатом на `libx264`.
8. Отчёт `отчёт.txt` и `clips.json` в папке `<запись>_clips`.

Фильтр мата (`is_profane`) работает по корням через регулярки с исключениями. Он проверен:
ловит все формы мата из теста и не трогает «тихую», «себе», «небо», «оскорблять»,
«страхуй», «мандарин», «мудрый» и т.п. **Любое изменение фильтра — только вместе с
тестами на эти слова.**

Что проверено (на синтетическом видео в Linux): поиск моментов, точное попадание звука
на мат, субтитры, зум, звуки на выбор, окно. Качество клипа без эффектов против исходника:
SSIM 0.998.

Что **не** проверено: реальная работа Whisper на RTX 5080 (архитектура Blackwell) под
Windows. Это первое, что надо проверить (этап 0).

## 3. Жёсткие правила

1. **После каждого этапа приложение должно запускаться и нарезать видео.** Не ломай
   рабочее ради следующего пункта.
2. **Перед каждым этапом делай коммит в git** (заведи локальный репозиторий в первый же
   раз), чтобы можно было откатиться.
3. **Никогда не удаляй файлы пользователя насовсем.** Отклонённые клипы и всё остальное
   удаляется только в корзину Windows (`send2trash`). Исходные записи OBS только читаются.
4. **Никакой автоматической публикации через браузер-ботов** (кликанье по сайтам,
   Selenium/Playwright от имени пользователя). Это нарушает правила площадок и грозит баном.
   Публикацию нажимает сам пользователь.
5. **Хук берётся только из того же клипа.** Кусок из другого места записи в клип
   попасть не может ни при каких настройках.
6. **Встроенные звуки генерируются ffmpeg.** Не скачивай чужие звуки и мемы из интернета.
7. Вся логика обработки — в ядре (`autoclip.py` или модули рядом), интерфейс только
   вызывает её. Ядро должно работать и без окна, из консоли.
8. Тексты интерфейса — по-русски, коротко, без «пожалуйста» и восклицательных знаков.
9. Если что-то в ТЗ непонятно или противоречит реальности (например, сайт поменял адрес
   загрузки) — спроси Гошу, не выдумывай.

## 4. Этапы

Делай по порядку. В конце каждого этапа: проверка по критериям, коммит, короткий отчёт
Гоше простыми словами, что изменилось и что проверить ему самому.

### Этап 0. Проверка базы на реальной записи

- Прогнать `autoclip.py` на реальной записи OBS 20–30 минут.
- Убедиться, что Whisper работает на видеокарте. Если на Blackwell не грузится
  (ошибки cuBLAS/cuDNN, «no kernel image»), разобраться: версии `ctranslate2`,
  `nvidia-cublas-cu12`, `nvidia-cudnn-cu12`. Откат на CPU оставить как запасной вариант.
- Проверить `h264_nvenc`.
- **Готово, когда:** клипы нарезаны, расшифровка шла на GPU, время работы записано в отчёт.

### Этап 1. Ядро как библиотека и модель данных

- `process()` принимает колбэки прогресса (этап, процент, сообщение) и флаг отмены.
- Ввести «проект записи»: папка `<запись>_clips` содержит `project.json` со всеми
  клипами. Для каждого клипа хранить: файл, начало/конец в исходнике, оценку и её разбор,
  название, точки зума, хук (есть/нет, откуда взят), статус, личные настройки клипа
  (переопределения хука, зума, мата, субтитров), дату создания, отметки публикации.
- Пересборка одного клипа по его записи в `project.json` без повторной расшифровки.
- Пользовательские данные (настройки, история) — в `%APPDATA%\AutoClip`, чтобы обновления
  программы их не затирали. Перенести туда `настройки.json`.
- **Готово, когда:** консольная нарезка работает как раньше, есть `project.json`,
  и отдельный клип пересобирается командой за секунды.

### Этап 2. Новый интерфейс на PySide6

tkinter не умеет нормально показывать видео и перетаскивать файлы наружу, поэтому
интерфейс переносится на **PySide6** (QMediaPlayer для просмотра, нативный drag-and-drop,
QFileSystemWatcher для папки). Тёмная тема.

Раскладка — **одно окно**, слева навигация по разделам:

- **Нарезка** — зона перетаскивания записи (и кнопка выбора), галочки по умолчанию для
  всех клипов, кнопка «Нарезать», прогресс по шагам, лог.
- **Клипы** — список клипов и редактор выбранного клипа (этап 6).
- **Подборка** — еженедельная подборка (этап 7).
- **Настройки** — всё редкое: экспорт, звуки, папка OBS, ник, хэштеги, языковая модель.

Галочки на экране «Нарезка»: Субтитры, Зум, Хук, Мат звуком (+ выбор звука и кнопка
прослушать), Метки, Ник в углу. Плюс: количество клипов, раскладка (вебка сверху / снизу /
по центру), пресет экспорта. Всё запоминается между запусками.

Просмотр клипа можно **открепить в отдельное окно** (например, на второй монитор) и вернуть
обратно. Окна соцсетей — отдельные (этап 11). Других отдельных окон не делать.

- **Готово, когда:** всё, что умеет текущий `gui.py`, работает в новом окне; старый
  `gui.py` удалён; `AutoClip.bat` запускает новое окно; `install.bat` ставит PySide6.

### Этап 3. Пресет экспорта

Пресет по умолчанию «TikTok 1080p60»:

| Параметр | Значение |
|---|---|
| Разрешение | 1080×1920 (вертикально) |
| Частота кадров | 60 fps |
| Кодек | H.264 (`h264_nvenc`, откат `libx264`) |
| Битрейт | 18 000 Кбит/с, постоянный (CBR) |
| Контейнер | MP4, `+faststart` |
| Цвет | Rec. 709: `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv` |
| Звук | AAC 320 кбит/с, 48 кГц (не менять) |

- Если исходник не 1080×1920 — масштабировать (lanczos).
- Если исходник не 60 fps — привести к 60 и **один раз предупредить** в логе, что плавнее
  от этого не станет, лучше писать в OBS сразу 60.
- Пресеты хранятся списком, в «Настройках» можно добавить свой.
- **Готово, когда:** `ffprobe` на клипе показывает 1080×1920, 60/1, h264, ~18 Мбит/с,
  bt709 во всех трёх полях цвета.

### Этап 4. Хук в начале

- Для каждого клипа решать, ставить ли хук:
  - **ставить**, если внутри клипа есть яркий момент реакции (приоритет — голос и смех,
    а не просто громкий звук игры) и клип сам не начинается с действия;
  - **не ставить**, если яркого момента нет или (при наличии модели) тизер раскроет
    развязку шутки.
- Хук: 1–2 секунды этого момента в самом начале, короткая склейка, затем клип с начала.
  Хук — повтор куска того же клипа (правило 5).
- Общая галочка «Хук» + переопределение для отдельного клипа.
- В отчёте и `project.json`: поставлен ли хук, откуда взят, почему.
- Тест: хук всегда внутри интервала клипа.

### Этап 5. Метки из OBS (необязательно)

- В OBS 30.2+ при записи в формат Hybrid MP4 есть горячая клавиша «Добавить маркер главы».
  Проверь, что такие метки читаются через `ffprobe -show_chapters`. Если нет — найди, как
  OBS их сохраняет, и сообщи Гоше.
- Метку ставят **после** смешного момента (через 5–20 с). Поэтому окно поиска — примерно
  30 с назад от метки; начало момента определять по речи и громкости.
- Моменты с меткой получают большой приоритет в отборе. Нет меток — всё работает как раньше.
- Клипы из меток помечаются в списке.
- Дать Гоше короткую инструкцию: как включить Hybrid MP4 и повесить хоткей на стримдек.

### Этап 6. Редактор клипа (раздел «Клипы»)

- Список клипов с оценкой, названием и пометками (хук / без хука / тихое начало / метка /
  статус). Фильтры: все, новые, хорошие, выложены.
- Для выбранного клипа:
  - просмотр с перемоткой (можно открепить);
  - свои галочки: хук, зум, мат, субтитры;
  - сдвиг начала и конца кнопками ±2 с (и точный ввод времени);
  - «Пересобрать» — переделывает только этот клип;
  - «Хороший», «В корзину»;
  - «Сохранить как…», «Показать в папке» (`explorer /select,`).

### Этап 7. Статусы и еженедельная подборка

- Статусы: **новый**, **хороший** (одобрен Гошей), **выложен**, **отклонён** (файл в корзину).
- Раздел «Подборка»: из клипов со статусом «хороший» или «выложен» за последние 7 дней
  собрать один ролик, по убыванию оценки, с короткими переходами. Гоша может убрать клипы
  из подборки и поменять порядок перед сборкой.
- Формат подборки уточни у Гоши (см. раздел 6).

### Этап 8. Обложки

- Для каждого клипа сохранять картинку-обложку `<клип>.jpg`: кадр с самой яркой реакцией.
  Если подключён OpenCV — предпочитать кадр, где в зоне вебки есть лицо.

### Этап 9. Ник в углу

- Галочка «Ник в углу» (по умолчанию выключена). Текст по умолчанию `Final_KFC_Boss`,
  настраиваются угол, размер, прозрачность. Небольшой и не перекрывает субтитры.
- Это тестовая функция: если Гоше не понравится, её убирают.

### Этап 10. Хэштеги и описание

- Постоянный набор хэштегов (в «Настройках»), добавляется к каждому клипу.
- Добавки по площадкам, например `#shorts` для YouTube.
- При подключённой модели — 2–3 тега по содержанию клипа и нормальное название.
- Итог: 3–5 хэштегов, не больше. Описание можно править перед публикацией.
- Кнопка «Копировать описание».

### Этап 11. Публикация

- Кнопки у клипа: TikTok, YouTube, Instagram, «Во все три».
- Каждая открывает **отдельное окно браузера в режиме приложения** прямо на странице загрузки:
  Edge (`msedge --app=URL --user-data-dir=<папка профиля AutoClip> --no-first-run`),
  если Edge нет — браузер по умолчанию. Отдельный профиль: Гоша входит один раз,
  вход запоминается.
- Адреса (проверь, что актуальны, при необходимости спроси):
  - TikTok: `https://www.tiktok.com/tiktokstudio/upload`
  - YouTube: `https://www.youtube.com/upload`
  - Instagram: `https://www.instagram.com/` — если прямой страницы создания нет, сообщи
    Гоше, что нужно один раз нажать «+».
- «Во все три» — три окна рядом на основном мониторе.
- По нажатию: описание копируется в буфер, клип можно **перетащить из списка прямо в
  окно загрузки** (QDrag с `QMimeData.setUrls`). Запасной вариант — «Показать в папке».
- После публикации кнопка «Отметить выложенным» (для каждой площадки отдельно).
- Правило 4: никаких автокликов и заполнения форм за пользователя.

### Этап 12. Слежка за папкой OBS

- В «Настройках» указывается папка записей OBS. Галочка «Следить за папкой».
- Новый файл: дождаться, пока OBS дописал (размер не меняется ~10 с и файл открывается).
- Записи короче порога (по умолчанию 5 минут, настраивается) не предлагать — это тесты.
- Показать уведомление Windows / окно: «Новая запись: <имя>, <длительность>, меток: N.
  Нарезать?» — кнопки «Нарезать» и «Не надо». Отказ запоминается для этого файла.
- Программа может жить в трее, чтобы слежка работала с закрытым окном.

### Этап 13. Прогноз залёта

1. **Разбор по правилам удержания** для каждого клипа, вместо одной цифры:
   - есть ли крючок в первые 1–2 секунды;
   - тишина в начале;
   - длина;
   - паузы внутри;
   - где эмоциональный пик (раньше — лучше);
   - плотность речи.

   Показывать понятными фразами: «тихое начало — первые 3 с без звука».
2. **Сбор просмотров через вопрос.** Когда Гоша отмечает клип выложенным на площадке, программа
   запоминает дату и (по желанию) ссылку на пост. Через 3 дня (настраивается: 2–7) при
   запуске программы появляется окно: «Клип "<название>" выложен в TikTok 3 дня назад.
   Сколько просмотров?» Поля: просмотры (обязательно), процент досмотров (необязательно).
   Кнопки: «Сохранить», «Напомнить завтра», «Пропустить». Если вопросов накопилось
   несколько — показывать их одним списком, а не пачкой окон. По каждой площадке отдельно.
   Ответы хранятся у клипа в `project.json` и в общей истории в `%APPDATA%\AutoClip`.
3. **Обучение на двух сигналах:**
   - **оценки Гоши** («Хороший» = 1, «В корзину» = 0) — быстрый сигнал, учит его вкусу;
   - **реальные просмотры** (лог просмотров, нормированный по площадке) — медленный, но
     главный сигнал, учит тому, что заходит зрителям.

   Признаки клипа: громкость пика, смех, хук, длина, тихое начало, паузы, позиция пика,
   плотность речи, мат, метка со стримдека, оценка языковой модели. Модель простая
   (логистическая и линейная регрессия, scikit-learn), веса видны и объяснимы. Учится после
   ~30 оценок или ~30 клипов с просмотрами; до этого честно писать, что данных мало, и
   работать по эвристике. Итоговая оценка — смесь эвристики и модели, доля модели растёт
   с количеством данных.
4. **Вкус для языковой модели:** в запрос к модели добавлять 3–5 расшифровок клипов,
   которые Гоша отметил «Хороший» или которые набрали больше всего просмотров, как примеры.
5. **Потом, отдельно и по согласованию с Гошей:** импорт файла статистики YouTube Studio,
   автоматический сбор просмотров через YouTube Analytics API и Instagram Graph API.
   Для TikTok — только если появится одобренный доступ; иначе остаётся ручной ввод.
6. Не обещать «вирусность». Это оценка, а не прогноз просмотров.

### Этап 14. Автообновление (последним, необязательно)

Пока Гоша дорабатывает программу через тебя в Claude Code прямо на этом компьютере, файлы
меняются на месте, и скачивать ничего не нужно. Автообновление нужно, только если
разработка будет идти с другого места. Тогда:

- код в репозитории GitHub (какой — уточни у Гоши);
- при запуске проверка последнего релиза, скачивание архива, замена файлов программы,
  перезапуск; пользовательские данные в `%APPDATA%\AutoClip` не трогаются;
- версия видна в заголовке окна.

## 5. Проверка

- Юнит-тесты (`pytest`) на: фильтр мата (включая слова-исключения выше), смех, выбор
  клипов, хук внутри клипа, сдвиг начала и конца, статусы.
- После этапов, где меняется рендер: прогон на реальной записи и проверка `ffprobe`.
- Интерфейс проверяй запуском и скриншотом.
- Перед отчётом Гоше — проверь сам, что то, о чём пишешь, действительно работает.
